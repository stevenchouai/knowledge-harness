01

Fake vault contract files

The demo starts by creating only the contract files the harness expects: AGENTS.md, PROMPTS.md, and wiki/_index.md. These files are tiny, sanitized, and made for public inspection.

Contract surface

fake-vault/
  AGENTS.md
  PROMPTS.md
  wiki/_index.md
02

Dry-run prompt assembly

knowledge-harness demo points the harness at that fake vault and assembles the same prompt shape used by real queries. The dry-run path writes prompt.txt but stops before any model invocation.

Prompt proof

03

Run metadata and safety flags

The run metadata records the prepared command and safety flags. The public proof is that write_output=false, dry_run=true, no --add-dir vault grant appears, and the demo Codex path is intentionally missing.

run.json checks

  • real_vault_used=false
  • codex_used=false
  • write_output=false
  • dry_run=true
  • no --add-dir
04

Receipt formats for humans and tools

The demo can print the same proof as HTML, Markdown, or JSON. HTML is a browser-friendly card, Markdown is copy/pasteable for a README or review thread, and JSON is machine-readable for automation.

Receipt formats

HTML knowledge-harness demo --html
Markdown knowledge-harness demo --markdown
JSON knowledge-harness demo --json
05

Cleanup and no private data boundary

Everything is created under a temporary demo root. The receipt prints the cleanup command, and the only vault files in scope are the fake contract files above. No real Obsidian vault is read, no local config is rewritten, and no private notes are copied into this repository.

Boundary check

rm -rf $TMPDIR/knowledge-harness-demo-SAMPLE

not opened

not called

What a visitor should remember

knowledge-harness is concrete memory-runtime tooling. The public demo proves prompt assembly, run metadata, safety flags, and receipts with a fake vault, so the repo can explain the system without exposing private vault content or requiring Python installation.
